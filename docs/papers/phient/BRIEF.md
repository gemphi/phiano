# Brief for one Phient paper (read fully before writing)

You are writing ONE markdown paper in Phient's own series: sixteen papers that state, from the inside, what Phient's Phasor Language Models are, what has been built, what has been measured, and what has not. Read `PHIENT_FACTS.md` (same folder) first, then the source files listed for your paper (all local; read them with the Read tool). Nothing on the web is needed.

Rules, non-negotiable:
1. Every number comes from the source files or PHIENT_FACTS.md and is cited exactly as it stands there. If the sources disagree, say so and prefer the later document. Never invent a number, a result, a file, a function or a date. If a thing was proposed and not built, say "not built"; if it was not measured, say "not measured".
2. Open with the paradigm paragraph verbatim (in PHIENT_FACTS.md), right after the front matter.
3. Front matter:
   # <Title>
   *Phient papers, N of 16 · <date> · <one-line subject>*
4. Sixteen numbered sections `## <n>. <heading>`, each 380–450 words (about 6,500 words). Arc: 1 abstract; 2 the claim; 3 the mechanism, plainly, naming the actual types and functions from the sources; 4 what was measured and the numbers; 5 the one idea restated; 6–10 the substance of the subject in depth, with worked examples drawn from the sources (real words, real channels, real commands); 11 what it depends on and what depends on it in the PML family (phinet the parent; phical, phinum, phiqlm (planned), phifno, phiton its children; phiano, phiecs, phiace); 12 the next experiment, with the control named; 13 what is wrong or missing, plainly; 14 how it was found (the history in the docs, with the doc numbers); 15 what remains; 16 sources (the local paths read).
5. Style: the plain, exact voice of the existing Phient docs. Short sentences. No hype, no em-dash asides, no "not X but Y", no "worth noting", no bullet lists in body sections (tables and code blocks fine), no emoji.
6. Write the file to the exact path given. Nothing else. Do not modify any source file.
